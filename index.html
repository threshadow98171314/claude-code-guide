第 1 章　先搞懂基本觀念（給完全新手）

這一章不需要動手，只要讀懂。後面所有操作都建立在這些觀念上。讀完你會知道「session、context、token、工具、權限、模型」這些詞在講什麼。

1.1 Claude 是什麼？Claude Code 又是什麼？

Claude 是 Anthropic 公司開發的 AI 助手。你可以把它想成一位很聰明、讀過大量資料、會寫程式也會寫文章的同事。

Claude Code 是「讓 Claude 直接在你的電腦上幫你寫程式」的工具。一般的聊天 AI 只能回答你，你還得自己把程式碼複製貼上；Claude Code 則可以：

  • 自己打開、閱讀你專案裡的檔案
  • 直接修改程式碼
  • 在終端機執行指令（安裝套件、跑測試、啟動伺服器）
  • 使用 git（看差異、建立分支、commit）
  • 上網查文件

這種「會自己動手做事」的 AI，叫做 AI 代理（agent）。

💡 比喻：一般聊天 AI 像是「電話另一頭的顧問」，只能口頭建議；Claude Code 像是「坐在你旁邊、可以用你電腦的實習工程師」，會實際操作，但重要動作會先問你。

1.3 Session（工作階段）是什麼？

Session = 一段連續的對話，包含你說過的話、Claude 的回覆、它做過的所有動作。

你可以這樣想 說明
一個 session 就像一本「工作筆記本」 從你輸入 claude 開始，到你離開或 /clear 為止，都寫在同一本
每次 claude 都會開一本新筆記本 舊筆記本會保存在電腦裡（預設 30 天），可以用 /resume 或 claude -c 翻回來
同一個資料夾可以有很多本 例如「修登入 bug」一本、「寫新功能」一本，互不干擾

常用的 session 操作：

想做的事 怎麼做
開始新 session 在專案資料夾輸入 claude
回到最近一次的對話 claude -c（continue）
從清單挑一個舊對話 claude -r 或在 session 中輸入 /resume
幫 session 取名字 /rename 登入功能，之後 claude -r 登入功能 就能找回
換一個新任務、清空對話 /clear（舊對話仍可 /resume 找回）
從某一點分岔出另一條路 /branch

1.4 回合（Turn）

你送出一則訊息，到 Claude 回覆完畢並停下來等你，叫做一個回合。一個回合裡 Claude 可能會呼叫好幾次工具。回合結束時你會看到類似 ✻ Crunched for 12s 的耗時提示。

在 Claude 工作中，你仍然可以繼續輸入，訊息會排隊，等這個回合結束再送出；要立刻打斷，按 Esc。

1.5 Context（上下文）與 Context window（上下文視窗）

Context 是 Claude「此刻腦中能看到的所有東西」：系統說明、你的 CLAUDE.md、對話歷史、讀過的檔案內容、指令輸出……

Context window 是這個容量的上限。目前 Claude 的主力模型有 100 萬 token 的視窗。

💡 比喻：context window 像一張辦公桌。桌子很大，但東西堆太多，重要文件就容易被淹沒，Claude 的表現也會下降；而且桌上東西越多，每次「看一遍」的成本也越高。

用 /context 可以看到桌上目前放了什麼、還剩多少空間：

當 context 快滿時，Claude Code 會自動壓縮（auto-compact）：把較早的對話摘要成短短一段，騰出空間。你也可以手動 /compact。

1.6 Token 是什麼？

Token 是 AI 計算文字量的單位，大約是：英文 1 個單字 ≈ 1～1.3 token；中文 1 個字 ≈ 1～2 token。

Token 和兩件事有關：

  1. 容量：context window 以 token 計算。
  2. 費用／額度：用 API 付費是依 token 計價（例如 Opus 5.5 每百萬輸入 token 4 美元）；用訂閱方案則是消耗你的 5 小時與每週用量額度。

1.8 權限（Permissions）：Claude 什麼時候會先問你？

因為 Claude 能改你的檔案、跑指令，所以有權限系統保護你。當它要做有風險的事，會跳出確認框：

上圖中紅色是要刪除的行、綠色是要新增的行。你可以選：

  • 1. Yes：只允許這一次
  • 2. Yes, and switch to accept edits：這個 session 之後的修改都自動允許
  • 3. No：拒絕（可以再告訴 Claude 你想怎麼改）

要跑指令時也一樣：

「Yes, and don't ask again for: npm test *」會把這條規則記住，以後同類指令不再問。

權限模式決定「問的頻率」，按 Shift+Tab 切換（第 9 章詳解）：

模式 一句話說明 適合
Manual（手動） 除了讀取，什麼都先問 剛開始用、重要專案
Accept edits（自動接受編輯） 改檔不問，跑指令會問 信任方向、想快一點
Plan（規劃） 只研究不修改，先給你計畫 大改動之前
Auto（自動） 由安全分類器把關，低風險直接做、高風險擋下 目前互動模式的預設

1.9 模型（Model）與推理強度（Effort）

  • 模型是 Claude 的「大腦型號」。目前有 Opus 5.5（預設，聰明且相對便宜）、Sonnet 5.5（快又便宜）、Haiku 5.5（最快最便宜）、Fable 5.1（最強也最貴，需權限）。用 /model 切換。
  • Effort 是「這次要想多深」：low → medium → high → xhigh → max。越高越仔細但越慢、越耗額度。Opus 5.5 預設 medium。用 /effort 調整。

1.10 CLAUDE.md：給 Claude 的「專案說明書」

每次開新 session，Claude 都是「第一天上班」。CLAUDE.md 是放在專案根目錄的 Markdown 檔，Claude 每次啟動都會先讀，就像新同事的入職手冊。裡面寫：怎麼安裝、怎麼跑測試、程式風格、哪些檔案不能動……

輸入 /init 讓 Claude 自動幫你產生第一版。詳見第 11 章。

💡 簡單判斷法：「我要的東西最後是一段文字／一份文件」→ Chat；「我要的東西最後是改好的程式碼／一個能跑的專案」→ Code。

同一個訂閱方案（Pro、Max、Team、Enterprise）的用量額度由 Chat 與 Claude Code 共用。

2.2 Chat 能做的事

  • 一般對話：問答、解釋觀念、翻譯、寫作、改稿。
  • 上傳檔案分析：PDF、Word、Excel、圖片、程式碼。
  • Artifacts：讓 Claude 產生可分享的網頁、文件、簡報、試算表。
  • Projects（專案）：把相關資料與指示集中，所有對話共用。
  • 研究（Research）與網路搜尋：查最新資訊並附來源。
  • Connectors：連 Google Drive、Gmail、Slack、Notion 等，讓 Claude 讀你自己的資料。
  • 記憶：記住你的偏好與背景，下次對話自動帶入。

適合「還沒進入寫程式階段」的事，例如：先在 Chat 討論架構與需求，確定後再到 Code 實作。

桌面版與 CLI 的差異：

  • 桌面版沒有 dontAsk 模式；/config 在桌面版會開啟設定頁而不是終端機選單。
  • 桌面版會自行設定部分環境變數（例如本機 session 的 API 逾時），所以在設定檔改這些變數可能無效。
  • 雲端 session 只支援 Accept edits、Plan、Auto 三種模式。
  • 桌面版的 .claude/launch.json 可設定 dev server，讓 Claude 自動開瀏覽器驗證改動。

2.6 其他你該知道的基礎知識

  • 終端機（Terminal）：輸入文字指令操作電腦的視窗。macOS 是「終端機」App；Windows 是 PowerShell 或 Windows Terminal。第 3 章會教最基本的操作。
  • 專案資料夾：Claude Code 以「你啟動它的資料夾」為工作範圍。請先 cd 到你的專案再執行 claude。
  • Git：版本控制工具，能記錄每次修改、隨時還原。強烈建議專案都用 git 管理，Claude 改壞了可以輕鬆回復。
  • 訂閱 vs API：用 claude.ai 訂閱登入，費用包含在月費內（有額度上限）；用 Claude Console API key，則依 token 用量計費。
  • 安全意識：Claude Code 能執行指令，請只在你信任的資料夾使用；不要把密碼、金鑰寫在對話裡；重要操作仔細看確認框。

第 3 章　安裝、登入與第一次啟動

3.1 終端機 30 秒入門

Claude Code 主要在終端機中使用。你只需要會三件事：

指令 作用 例子
cd 路徑 進入某個資料夾 cd ~/projects/my-app（Windows：cd C:\Users\你\projects\my-app）
ls（Windows PowerShell 也可用 dir） 列出目前資料夾內容 ls
pwd 顯示目前在哪個資料夾 pwd

開啟方式：macOS 按 Cmd+Space 搜尋「終端機」；Windows 按 Win 搜尋「PowerShell」或「Terminal」。

💡 不想用終端機？可以直接用 Claude 桌面版的 Code 分頁（第 2 章），概念完全相同。

3.2 安裝

需要：一個 Claude 訂閱（Pro／Max／Team／Enterprise）或 Claude Console 帳號。

macOS／Linux／WSL：

curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell（提示字元是 PS C:\>）：

irm https://claude.ai/install.ps1 | iex

Windows CMD（提示字元是 C:\>）：

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

原生安裝版會在背景自動更新。也可用 brew install --cask claude-code（macOS）或 winget install Anthropic.ClaudeCode（Windows），但這兩種不會自動更新。

裝好後開一個新的終端機視窗，確認版本：

claude --version
# 2.1.312 (Claude Code)

Windows 建議另外安裝 Git for Windows，Claude 才能使用 Bash 工具；沒裝的話會改用 PowerShell。

常見安裝問題

狀況 解法
claude: command not found 關掉終端機重開；仍不行請依官方「Troubleshoot installation」把安裝路徑加入 PATH
'irm' is not recognized 你在 CMD，請改用 CMD 的那行指令或打開 PowerShell
The token '&&' is not a valid statement separator 你在 PowerShell，請改用 PowerShell 的那行

第 8 章　settings.json：所有設定項目逐一說明

/config 面板只列出常用選項。所有設定都能寫在 settings.json 檔案裡。本章先教你設定檔的觀念，再把 v2.1.312 的全部設定 key（共 245 項）逐一說明並附範例。

8.1 設定檔在哪裡？

範圍 檔案位置 影響誰 適合放
使用者 ~/.claude/settings.json（Windows：C:\Users\你\.claude\settings.json） 你在這台電腦的所有專案 個人偏好：主題、語言、預設模型
專案（共享） 專案內 .claude/settings.json 所有用這個專案的人（commit 進 git） 團隊共用的權限、hooks、plugins
專案（本機） 專案內 .claude/settings.local.json 只有你、只在這個專案（自動排除在 git 外） 個人例外設定；權限提示選「不再詢問」時寫在這裡

剛安裝時這些檔案都不存在，第一次在 /config 改設定或回答「不再詢問」時才會自動建立。也可以自己用編輯器建立。

8.2 優先順序：誰說了算？

同一個設定寫在多個檔案時，上面的蓋過下面的：

① 組織管理（最高，無法被覆蓋）
② 命令列 --settings（只影響這次）
③ 專案本機 .claude/settings.local.json
④ 專案共享 .claude/settings.json
⑤ 使用者 ~/.claude/settings.json（最低）

例外：清單類設定（例如 permissions.allow）會合併而不是覆蓋。

🔍 設定沒生效？在 session 中輸入 /status，看「Setting sources」列出實際載入了哪些檔案；在終端機執行 claude doctor 可列出寫錯而被忽略的設定。

8.3 設定檔的寫法

設定檔是嚴格的 JSON：用大括號包起來、key 用雙引號、項目之間用逗號，最後一項後面不能有逗號，也不能寫註解。

{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "language": "繁體中文",
  "model": "opus",
  "outputStyle": "Explanatory",
  "permissions": {
    "allow": ["Bash(npm run test *)", "Bash(git diff *)"],
    "deny": ["Read(./.env)"]
  }
}
  • 第一行 $schema 讓 VS Code 等編輯器提供自動完成與錯誤提示，強烈建議加上。
  • 本章表格中的「範例」是一個片段，貼進大括號內即可；有多個項目時記得用逗號分隔。
  • 存檔後大部分設定會立即生效（Claude Code 會監看設定檔）；model 與 effort 要在 session 中用 /model、/effort 才會即時切換。
  • 懶得手改？在 session 中輸入 /update-config 你想要的設定，Claude 會幫你改對的檔案。

8.4 只想試一次？

claude --settings '{"model": "sonnet", "outputStyle": "Concise"}'

只影響這次啟動，不寫入任何檔案。

第 9 章　權限、Auto mode 與沙盒

Claude Code 能改檔、跑指令，所以「它可以做什麼、什麼要先問、什麼絕對不行」是最重要的安全設定。

9.1 六種權限模式

模式（設定值） 畫面顯示 不用問就能做 什麼時候用
Manual（default／manual） ⏸ manual mode on 只有讀取 第一次用、重要專案、想逐步審核
Accept edits（acceptEdits） ⏵⏵ accept edits on 讀取、改檔、工作目錄內常見檔案指令（mkdir、mv、cp、rm…） 信任方向，想加快但仍想審核指令
Plan（plan） ⏸ plan mode on 讀取與安全的查詢指令；核准計畫前不能改檔 大改動前先討論方案
Auto（auto） ⏵⏵ auto mode on 全部，但每個動作先經分類器審查 互動模式的預設；日常使用
Don't ask（dontAsk） ⏵⏵ don't ask on 只有讀取與事先核准的工具，其他直接拒絕 自動化腳本、CI
Bypass（bypassPermissions） ⏵⏵ bypass permissions on 幾乎全部，完全不問 只在隔離的容器／虛擬機中使用

切換方式：

  • 互動中按 Shift+Tab（桌面版用模式選擇器或 Ctrl/Cmd+Shift+M）。
  • 啟動時指定：claude --permission-mode plan。
  • 設為預設："permissions": { "defaultMode": "acceptEdits" }（auto 與 bypassPermissions 不能寫在專案設定檔，避免別人替你開大門）。

🔒 兩條永遠成立的規則：① deny（禁止）規則在任何模式都有效，包括 bypass。② 寫入 .git、.claude、.bashrc 等受保護路徑，除 bypass 外都不會自動核准。

9.3 Auto mode 深入了解

Auto mode 用一個獨立的安全分類器模型，在每個動作執行前審查。它只看你的要求與 Claude 打算做的動作，看不到檔案或網頁內容，因此惡意網頁中的「指令」騙不了它。

預設會擋下 預設允許
curl … | bash 下載後執行 工作目錄內的檔案操作
把敏感資料送到外部 依 lock 檔安裝相依套件
正式環境部署、資料庫 migration 讀 .env 並送給對應的 API
git push --force、git reset --hard 唯讀的網路請求
terraform destroy 之類的破壞操作 推送到目前 repo 的一般分支
合併未核准的 PR、提交秘密資訊
  • 連續被擋 3 次或累計 20 次，會暫停 Auto mode 改回詢問。
  • 被擋的動作會出現在 /permissions 的 Recently denied，可以手動重試。
  • 你在對話中說「不要 push」，分類器也會當成限制。
  • 用 /auto-mode-setup 讓它認識你的環境（例如哪台是測試機）。
  • claude auto-mode defaults 可看內建規則。

⚠️ Auto mode 能大幅減少打擾，但不保證 100% 安全。敏感操作請搭配 deny 規則、hooks、沙盒。

9.4 自訂規則：allow／ask／deny

用 /permissions 管理，或寫進設定檔：

{
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "WebFetch(domain:github.com)"
    ],
    "ask": ["Bash(git push *)"],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Bash(rm -rf *)"
    ]
  }
}
規則寫法 意思 範例
Bash(指令) 完全符合的指令 Bash(npm run build)
Bash(開頭 *) 以此開頭的指令 Bash(git log *)
Read(路徑)／Edit(路徑) 讀取／修改檔案，支援 ** Edit(src/**)
WebFetch(domain:網域) 可抓取的網站 WebFetch(domain:docs.python.org)
mcp__伺服器 或 mcp__伺服器__工具 MCP 工具 mcp__github__create_issue
Agent(名稱) 某個子代理 Agent(Explore)
工具(參數:值) 依參數比對 Agent(model:opus)

路徑寫法：./ 相對專案、~/ 家目錄、// 絕對路徑。判斷順序：deny 優先於 ask，ask 優先於 allow。

💡 懶得自己寫？/fewer-permission-prompts 會分析你最近的紀錄，自動建議白名單。

9.5 沙盒（Sandbox）

沙盒由作業系統強制限制 Claude 執行的指令能碰到哪些檔案與網路。macOS 用 Seatbelt，Linux 與 WSL2 用 bubblewrap；原生 Windows 不支援。

開啟：輸入 /sandbox，或設定 "sandbox": { "enabled": true }。/sandbox 會先檢查相依套件：

（Linux 需要 bubblewrap 與 socat，畫面會告訴你怎麼裝。）

面向 預設 調整用的設定
寫入 只能寫工作目錄與暫存資料夾 filesystem.allowWrite／denyWrite
讀取 大部分可讀（包括 ~/.ssh，建議封鎖） filesystem.denyRead／allowRead
網路 經本機 proxy，允許清單預設是空的 network.allowedDomains／deniedDomains 
{
  "sandbox": {
    "enabled": true,
    "filesystem": { "denyRead": ["~/.ssh", "~/.aws"] },
    "network": { "allowedDomains": ["github.com", "*.npmjs.org", "pypi.org"] },
    "excludedCommands": ["docker compose *"]

}

沙盒內執行的指令會自動核准（不再一直問），因為作業系統已經擋住了危險範圍。注意沙盒只管 shell 指令，Claude 的讀寫檔工具、MCP、hooks 不在沙盒內。

  • 同一個 Opus 模型，速度最高約 2.5 倍，品質不變，單價較高（Opus 5.5 為 $8／$40）。
  • 開關：/fast 或 Alt+O（Mac：Option+O）；開啟時輸入框旁出現 ↯。
  • 訂閱方案使用 Fast mode 會從 usage credits（額外儲值） 扣款，不含在月費額度裡；需要先開啟 usage credits。Team／Enterprise 需管理員開放。
  • 小技巧：在對話一開始就開，中途開會用高價重算整段 context 一次。

10.4 Context 管理

上圖解讀：

項目 意思
32.7k/1m tokens (3%) 已用 3.27 萬，上限 100 萬

保持 context 健康的習慣：

  1. 一個任務一個對話：換題目就 /clear。
  2. 主動壓縮：/compact 只保留資料庫結構的決定。
  3. 把吵雜工作交給子代理：大量搜尋、log 分析讓 subagent 做，只回傳摘要。
  4. 精簡 CLAUDE.md：長流程改寫成 skill（需要時才載入）。
  5. 關掉用不到的 MCP：每個 MCP 工具定義都佔空間。

10.5 省額度的實用技巧

  • 例行工作用 medium 甚至 low；需要時才 ultrathink。
  • 子代理用 Sonnet：設定 "env": { "CLAUDE_CODE_SUBAGENT_MODEL": "sonnet" }。
  • 經常 /usage 看哪個 skill、MCP 最耗。
  • 切換模型、effort、output style 會讓快取失效，下一次請求較貴，避免頻繁切換。
  • 很久沒動的大對話，重新開始可能比 /resume 更省。

- 資料庫 migration 要另開 PR

12.1 Skills（技能）

Skill 是一個資料夾，裡面有 SKILL.md。平時只有名稱和描述佔空間，Claude 判斷相關或你輸入 /名稱 時才載入完整內容。

放在哪裡：

範圍 路徑
個人（所有專案） ~/.claude/skills/名稱/SKILL.md
專案（commit 分享） .claude/skills/名稱/SKILL.md
Plugin 內 plugin/skills/名稱/SKILL.md（呼叫：/plugin名:skill名）

範例：.claude/skills/release-notes/SKILL.md

---
name: release-notes
description: 依 git 紀錄撰寫版本說明。使用者要求寫 changelog 或 release notes 時使用。
argument-hint: [版本號]
allowed-tools: Bash(git log *), Bash(git describe *)
disable-model-invocation: true
---

## 上個版本以來的提交
!`git log $(git describe --tags --abbrev=0)..HEAD --oneline`

## 請你
為版本 $ARGUMENTS 撰寫 release notes：
1. 分成「新功能／修正／破壞性變更」
2. 每條一句話，用使用者看得懂的語言
3. 輸出 Markdown

使用：/release-notes 2.4.0。

常用欄位 作用
description 最重要，Claude 靠它判斷何時使用
disable-model-invocation: true 只能由你手動呼叫（適合部署等有副作用的流程）
user-invocable: false 不出現在 / 選單，只給 Claude 當背景知識
allowed-tools 執行時預先核准的工具
argument-hint、$ARGUMENTS、$0、$1 參數提示與取用
!`指令` 送給 Claude 前先執行並嵌入結果
context: fork + agent: Explore 交給子代理在背景執行
model、effort 執行時改用的模型與強度
paths 只在處理符合的檔案時自動觸發

舊的 .claude/commands/名稱.md 自訂指令仍可用，但新的建議都寫成 skill。最簡單的建立方法：做完一件事後說「把剛剛的流程做成一個 skill」。

管理：/skills（t 依大小排序、Space 切換可見）、/skill-doctor（找出吃 context 又少用的 skill）、設定 skillOverrides 隱藏特定 skill。

12.2 Subagents（子代理）

子代理在獨立的 context 工作，只把摘要交回，主對話保持乾淨。

內建子代理：

名稱 用途
Explore 快速唯讀搜尋程式碼
Plan Plan 模式中的研究
general-purpose 需要查也需要動手的多步驟任務
claude-code-guide 回答 Claude Code 用法問題
statusline-setup /statusline 時使用

自訂子代理：放在 .claude/agents/（專案）或 ~/.claude/agents/（個人）。最簡單是直接說「幫我建立一個程式碼審查的 subagent」。

---
name: code-reviewer
description: 程式碼審查專家。程式改動後主動使用。
tools: Read, Glob, Grep, Bash(git diff *)
model: sonnet
effort: high
---

你是資深審查員。檢查正確性、安全性、可讀性，
每個問題列出 檔案:行號、原因與修正建議。
常用欄位 作用
name、description 必填；description 決定 Claude 何時派它
tools／disallowedTools 可用／禁用的工具
model sonnet、opus、haiku、fable、inherit
permissionMode、effort、maxTurns 權限、強度、回合上限
skills、mcpServers、hooks 預載的 skill、專屬 MCP 與 hooks
memory 讓它有自己的長期記憶（user／project／local）
isolation: worktree 在獨立 git worktree 中工作
background: true 永遠在背景執行

呼叫方式：「用 code-reviewer 檢查我的改動」、@"code-reviewer (agent)"、或 claude --agent code-reviewer 讓整個 session 都用它。

背景與 Fork：

  • 主對話派出的子代理預設在背景跑，你可以繼續做別的；它要權限時會在主畫面詢問。
  • Fork 子代理會繼承整段對話（不用重新解釋背景），用 /subtask 任務 啟動，結果回到本對話。
  • 分不清楚三個指令？/subtask＝派分身做完回報；/fork＝複製成另一個獨立背景 session；/branch＝分岔並切換過去。

12.3 Hooks（掛鉤）

Hook 讓某件事每次都一定發生，不靠 Claude 記得。例如：改完檔自動格式化、阻擋改 .env、需要你時跳通知。

常用事件：

事件 何時觸發 常見用途
PreToolUse 工具執行前（可阻擋） 擋危險指令、保護檔案
PostToolUse 工具成功後 自動格式化、跑 lint
UserPromptSubmit 你送出訊息時 加入額外背景、檢查敏感字
Notification Claude 需要你時 桌面通知
Stop Claude 回答完 檢查任務是否真的完成
SessionStart session 開始（含壓縮後） 載入環境資訊
PreCompact／PostCompact 壓縮前後 保存重要資訊
SubagentStart／SubagentStop 子代理開始／結束 記錄
FileChanged、CwdChanged 檔案變動、切換目錄 自動載入 .env
其他 PermissionRequest、PermissionDenied、PostToolBatch、SessionEnd、WorktreeCreate、PreModelSwitch… 進階用途

範例 1：改完檔自動跑 Prettier（.claude/settings.json）

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }
        ]
      }
    ]
  }
}

範例 2：禁止修改 .env——腳本 .claude/hooks/protect.sh（記得 chmod +x）：

#!/bin/bash
FILE=$(jq -r '.tool_input.file_path // empty')
if [[ "$FILE" == *".env"* ]]; then
  echo "不可以修改 $FILE" >&2
  exit 2   # exit 2 = 阻擋，stderr 會告訴 Claude 原因
fi
exit 0     # exit 0 = 放行

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect.sh", "onFailure": "block" }
        ]
      }
    ]
  }
}

"onFailure": "block"：腳本本身出錯或逾時也當作阻擋，安全用途建議加上。

範例 3：需要你時跳 Windows 通知（PowerShell）

{
  "hooks": {
    "Notification": [
      { "hooks": [ { "type": "command", "command": "powershell -c \"[console]::beep(800,300)\"" } ] }
    ]
  }
}

Hook 類型：command（執行指令）、http（POST 到網址）、mcp_tool、prompt（讓模型判斷 ok/不 ok）、agent（實驗性）。

⚠️ Hook 以你的權限執行。審查別人 commit 的 hooks；全部停用用 "disableAllHooks": true。

# 本機程式（-- 後面是啟動指令）

12.6 Mods（2026/10 新功能）

Mod 是一種用 JavaScript／TypeScript 寫、在 Claude Code 內部執行的 plugin，可以：

  • 畫出面板、按鈕、提示框上方的資訊列
  • 改造內建介面（例如 spinner 顯示工具次數）
  • 攔截工具呼叫（例如危險指令先顯示影響範圍再讓你決定）
  • 新增立即執行的 /指令

做法：直接請 Claude「做一個 mod，在提示框上方顯示 context 使用量」。內建的 /diff 面板、AGENTS.md 讀取其實就是 mods。關閉全部：--safe-mode（一次）或 "disableAllHooks": true。

⚠️ Mod 不在沙盒中，能讀寫你的檔案與秘密。只裝信任的；安裝前用 claude plugin validate 路徑 看它會做什麼。

15.2 給新手的十條最佳實踐

  1. 專案一定用 git，改壞了能救回來。
  2. 先問再改：先讓 Claude 讀懂、解釋，再要求修改。
  3. 大改動先 Plan：Shift+Tab 到 Plan 模式，看過計畫再執行。
  4. 給驗證方法：告訴它「完成的標準」（哪個測試要過、畫面要長怎樣）。
  5. 方向不對立刻 Esc，不要等它做完。
  6. 一個任務一個對話，換題目就 /clear。
  7. 重複講的事寫進 CLAUDE.md，重複的流程做成 skill。
  8. 仔細看權限詢問框，尤其是刪除、推送、部署。
  9. 秘密檔案設 deny：Read(./.env)。
  10. 每次看 /diff 再 commit。
